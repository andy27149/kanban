01架构概览

请求路径固定为：外部流量先到宿主机的 nginx，由 nginx 转发到只在回环地址监听的应用容器。容器内部不跑 nginx，证书、域名、HTTPS 全部在宿主机 nginx 这一层处理，容器本身对此无感知。

宿主机nginx

127.0.0.1:5000 →
Docker 容器gunicorn + Flask

持久化数据全部通过 bind mount 落在宿主机，容器可以随时重建而不丢数据：

02前置条件

  • 服务器已安装 Docker 与 Docker Compose：docker --version、docker compose version 都能正常输出。
  • 服务器已安装并运行 nginx（Docker 之外，作为系统服务）。
  • 已备妥一个用于登录上传页的密码，以及一段随机字符串作为 Flask session 密钥（第 03 节会用到）。

03首次部署

  1. 拉取代码 将仓库克隆到服务器，例如 /opt/kanban，进入该目录执行后续命令。
  2. 创建环境变量文件 
    cp .env.example .env
    编辑 .env，把 UPLOAD_PASSWORD（数据维护人登录密码）和 FLASK_SECRET_KEY 改成真实值： 
    python3 -c "import secrets; print(secrets.token_hex(32))"
    用输出结果填 FLASK_SECRET_KEY。.env 已加入 .gitignore，不会被提交。
  3. 创建持久化数据目录 data/data.json 必须预先写入合法的空 JSON 结构，不能用 touch 建成空文件——原因见第 06 节第一条。 
    mkdir -p data/uploads
echo '{"kpis": [], "charts": [], "tables": []}' > data/data.json
  4. 确认 config.yaml 按照 README.md"配置"一节，确认每个 KPI/图表/表格的 source_file、sheet 名、取数方式都已按需设置。
  5. 构建并启动 
    docker compose up -d --build
  6. 验证 
    curl -I http://127.0.0.1:5000/dashboard
    看到 200 OK（或正常跳转）即表示应用已在容器内启动成功。此时还没配 nginx，还不能从外网访问。

04配置 nginx 反向代理

在 nginx 里新增一个 server block（按实际域名调整 server_name）：

/etc/nginx/sites-available/kanban.conf 
server {
    listen 80;
    server_name kanban.example.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
nginx -t && systemctl reload nginx

如需 HTTPS，用 certbot 等工具直接在这个 server block 上申请证书；容器内部完全不需要感知证书的存在。

前提假设：当前 docker-compose.yml 把容器端口绑定在 127.0.0.1:5000，这意味着 nginx 必须和 Docker 容器跑在同一台机器上。如果之后 nginx 挪到独立的负载均衡机器或另一台主机，这里的绑定地址需要改成容器所在机器的内网 IP，并相应放开安全组/防火墙里该内网来源的访问。

05日常操作

上传新 Excel 数据

浏览器访问 https://你的域名/upload，用 UPLOAD_PASSWORD 登录后上传。上传会立即基于整个 uploads/ 目录重新生成 data.json，无需重启容器。

修改 config.yaml

data.json 只在每次 /upload 请求时重新生成——这是代码里唯一的重新生成入口。所以单纯 docker compose restart 不会让新的 config.yaml 生效，看板会继续显示旧配置下算出来的数据。

正确做法：编辑完 config.yaml 后，去 /upload 页面重新上传一次 Excel——哪怕文件内容没变，重新上传同一份文件也会用最新的 config.yaml 重新计算并覆盖 data.json。因为配置是每次上传请求时才从磁盘读取的，所以既不需要 restart，也不需要重新 build 镜像。

更新代码后重新部署

git pull
docker compose up -d --build

查看日志

docker compose logs -f kanban

备份数据

直接备份宿主机上的 data/ 目录（uploads/ 原始 Excel + data.json 解析结果）和 config.yaml，例如用 rsync/cp 定期同步到异地，不依赖容器内部状态。

停止服务

docker compose down

06关键注意事项

以下是实测和代码走查中确认过的真实风险点，按严重程度排序，建议部署前逐条过一遍。

空 data.json 会让 /api/data 直接 500 严重
现象

用 touch data/data.json 建一个 0 字节的空文件启动容器，看板首页直接报 500。

根因

/api/data 路由只对"文件不存在"这一种情况做了兜底，返回空结构；但"文件存在且是空的"会继续往下走到 json.load()，抛出 JSONDecodeError。

应对

按第 03 节 Step 3 的方式，首次创建时就写入 {"kpis": [], "charts": [], "tables": []}，而不是用 touch 建空文件。

.env 缺失或写错时，不安全的默认密钥会静默生效 严重
现象

如果 .env 没配好（文件缺失、变量名拼错、值为空），应用会悄悄回退成默认密码 changeme 和默认 session 密钥，容器日志里不会有任何一行警告。

根因

代码里确实写了警告逻辑，但它只在 python app.py 直接运行、__name__ == "__main__" 成立时才会打印。Docker 里用 gunicorn 启动是直接 import 应用工厂函数，不会经过这段 __main__ 分支，警告永远不会出现在 docker compose logs 里。

应对

不要依赖运行时警告。部署后手动核对一次：docker compose config 打印出来的环境变量确实是你设的真实值，不是默认值。

回环端口绑定不等于"外网访问不到" 严重
现象

docker-compose.yml 把端口绑定成 127.0.0.1:5000:5000，理论上外部流量到不了容器，只能走 nginx。

需要额外确认的点

这只挡住了"从公网直接连 5000 端口"这一种情况。云主机的安全组/本机防火墙（如 ufw）建议仍然显式挡掉 5000 端口的公网入站，做纵深防御——万一将来有人手滑把绑定地址从 127.0.0.1 改成了 0.0.0.0，安全组这一层还能兜底。

改 config.yaml 后不重新上传，配置不会生效 中等
现象

编辑完 config.yaml 只做了 docker compose restart，看板数据没有任何变化。

根因与应对

详见第 05 节"修改 config.yaml"——必须通过 /upload 重新上传一次文件才会用新配置重新生成 data.json。

上传文件名必须和 config.yaml 里的 source_file 完全一致 中等
现象

上传成功但某个 KPI/表格取值失败，页面提示"找不到表头"或类似错误。

排查方向

确认上传文件名（含中文、含扩展名）和 config.yaml 里对应 source_file 字段逐字符一致。跨系统传输中文文件名时（尤其是 macOS 与其他系统之间），要留意 Unicode 归一化形式不同导致"看起来一样、实际字节不同"的情况。

超大 Excel 上传可能触发 gunicorn 默认超时 中等
现象

上传解析在请求内同步完成；gunicorn worker 默认超时是 30 秒，如果 Excel 文件很大、sheet 很多，解析耗时可能超过这个值，请求被 worker 直接杀掉。

应对

如果观察到超大文件上传失败，在 Dockerfile 的 CMD 里给 gunicorn 加 --timeout 120（或更高）再重新 build。

容器日志会无限增长 提示
现象

Docker 默认的 json-file 日志驱动没有大小上限，长期运行后日志文件可能占满磁盘。

应对

在 docker-compose.yml 的 kanban 服务下加 logging 配置限制大小和文件数，例如 max-size: "10m"、max-file: "3"。
